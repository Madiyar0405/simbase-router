# Техническое описание API — XML Router (sbapi gateway)

## 1. Назначение

Сервис принимает входящие XML-запросы (SOAP-конверт), извлекает
идентификационный номер (БИН) из вложенных данных и маршрутизирует
сообщение в соответствующую целевую систему, формируя исходящий
XML-конверт в формате `sbapi` с авторизацией.

## 2. Общая схема взаимодействия

```
Внешняя система (Enbek(Через ВШЭП))
        │  POST /route  (SOAP-конверт, XML)
        ▼
      ВШЭП
        │  Проверка транспортной подписи
        │  Маршутизация данных по системам
        ▼
XML Router (данный сервис)
        │  извлекает БИН → определяет маршрут
        │  формирует sbapi-конверт
        ▼
     SimBASE
```

## 3. Метод API

### `POST /route`

Принимает XML-документ и обрабатывает его синхронно: определяет маршрут,
формирует и отправляет исходящее sbapi-сообщение, возвращает ответ целевой
системы.

**Заголовки запроса:**

| Заголовок      | Значение             | Обязательный |
|----------------|-----------------------|--------------|
| `Content-Type` | `application/xml`     | да           |

**Тело запроса (пример):**

```xml
<?xml version="1.0" encoding="UTF-8"?>
<SOAP-ENV:Envelope
        xmlns:SOAP-ENV="http://schemas.xmlsoap.org/soap/envelope/"
        xmlns:ns1="http://bip.bee.kz/SyncChannel/v10/Types">
    <SOAP-ENV:Body>
        <ns1:SendMessage>
            <request>
                <requestInfo>
                    <messageId>*******</messageId>
                    <serviceId>SQ_vacancy_request_Enbek</serviceId>
                    <messageDate>2026-07-20T11:32:00</messageDate>
                    <sender>
                        <senderId>Enbek</senderId>
                        <password>******</password>
                    </sender>
                </requestInfo>
                <requestData>
                    <data >Данные кандидата</data>
                </requestData>
            </request>
        </ns1:SendMessage>
    </SOAP-ENV:Body>
</SOAP-ENV:Envelope>
```

Вложенный XML внутри `<data>` может передаваться как в `CDATA`, так и в виде
обычного экранированного текста (`&lt;`, `&gt;`) — сервис поддерживает оба
варианта равнозначно.

**Ключевое поле для маршрутизации:** `cvRecruit/cv/iin` — по значению этого
поля определяется целевая система-получатель.

### Ответ

Сервис возвращает **тот же ответ**, что вернула целевая система (проксирование
без изменений), с `Content-Type: application/xml`.

**Пример успешного ответа:**

```xml
<?xml version="1.0" encoding="UTF-8"?>
<sbapi>
  <header>
    <interface id="218124291" version="8"/>
    <message id="1" ignore_id="yes" type="5000" created="2026-07-22T10:56:26Z"/>
    <error id="0"/>
  </header>
  <body>
    <!-- ответ целевой системы -->
  </body>
</sbapi>
```

**Коды ошибок (от целевой системы, проксируются как есть):**

| Код    | Описание                                                   |
|--------|--------------------------------------------------------------|
| `0`    | Успешно                                                       |
| `2001` | Ошибка синтаксического разбора XML (невалидный XML)           |
| `2011` | Ошибка структуры заголовка `auth` (неверные данные авторизации)|

**Ошибки самого роутера** (до обращения к целевой системе):

| HTTP-статус | Условие                                                 |
|-------------|---------------------------------------------------------|
| `400`       | Некорректный входящий XML (не удалось распарсить)       |
| `502`       | Не найден маршрут для указанного БИН                    |
| `500`       | Внутренняя ошибка (например, целевая система недоступна) |

## 5. Формат исходящего сообщения (в SimBASE)

Сервис формирует запрос в формате `sbapi`:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<sbapi>
  <header>
    <interface id="218124291" version="8"/>
    <message id="1" ignore_id="yes" type="5000" created="2026-07-22T10:56:26Z"/>
    <error id="0"/>
    <auth pwd="hash">BASE64(&lt;authdata msg_id="1" user="..." password="SHA3-512_HEX" msg_type="5000" user_ip="..." /&gt;)</auth>
  </header>
  <body>
    <function name="f_send_msg">
      <arg name="data">{...}</arg>
    </function>
  </body>
</sbapi>
```

- `Content-Type: application/soap+xml; charset=utf-8`
- Пароль хешируется алгоритмом **SHA3-512** (результат в hex), сам блок
  `<authdata>` кодируется в **base64**.

## 6. Конфигурация маршрутов

Маршруты (соответствие ИИН → целевая система) задаются в конфигурации
сервиса (`application.yml`): для каждого маршрута указывается URL целевой
системы, учётные данные (login/password) и список ИИН, которые направляются
на этот маршрут.

## 7. Безопасность

- Входящие данные проверяются на корректность XML (защита от XXE:
  `disallow-doctype-decl`).
- Учётные данные для каждого маршрута хранятся в конфигурации сервиса и не
  передаются во внешние логи в открытом виде (в логах фиксируется только
  факт отправки и HTTP-статус ответа).
- Соединение с целевыми системами — по HTTPS.

## 8. Технологический стек

- Java 17, Spring Boot 3.3
- Развёртывание: Docker (один образ/контейнер)
